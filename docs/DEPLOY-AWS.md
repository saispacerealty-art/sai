# Deploying on Amazon Web Services (AWS Amplify Hosting)

The website goes on **AWS Amplify Hosting**. The database, logins, file storage and server functions stay on **Supabase**, which already runs on AWS in Mumbai (ap-south-1), so nothing there moves.

```
Staff browser ──▶ AWS Amplify (website, HTTPS, security headers)
                     │
                     ▼
               Supabase on AWS Mumbai (database · logins · files · functions)
```

The repository has two folders: `frontend/` (the website, built by Amplify) and `backend/` (deployed to Supabase, ignored by Amplify). Already in this repository for AWS:

| File | What it does |
|---|---|
| `amplify.yml` | Build steps for `frontend/` (monorepo, `appRoot: frontend`): Node 22, `npm ci`, `npm run build`, publish `dist/` |
| `customHttp.yml` | Security headers (CSP, HSTS, no framing…) and caching for `frontend`. Generated by `node frontend/scripts/set-csp.mjs <project-ref>`; do not edit by hand |

Time needed: about 30 minutes.

## 0. Before you start

- The code is on GitHub (`saispacerealty-art/sai`) and up to date: `git push`.
- The Supabase project is set up: inside `backend/`, `npx supabase db push`, `npx supabase config push`, functions deployed (docs/DEPLOY.md steps 1–5).
- `customHttp.yml` names your current Supabase project. If you change project, run `node frontend/scripts/set-csp.mjs <project-ref>`, commit and push.

## 1. AWS account

1. Sign up at **aws.amazon.com** (needs a card; Amplify has a free tier).
2. Sign in to the AWS Console and pick the region **Asia Pacific (Mumbai) ap-south-1** (top right).
3. Turn on MFA for the root account: top right → Security credentials → Assign MFA.

## 2. Create the Amplify app

1. Console search → **AWS Amplify** → **Create new app**.
2. Choose **GitHub** → **Next** → authorize AWS Amplify and give it access to the `saispacerealty-art/sai` repository only.
3. Repository `saispacerealty-art/sai`, branch `main`. **Tick "My app is a monorepo"** and type `frontend` as the folder → **Next**.
4. App name `sai-space-crm`. Amplify finds `amplify.yml` automatically ("Build settings detected", app root `frontend`).
5. Open **Advanced settings → Environment variables** and add:

   | Variable | Value |
   |---|---|
   | `VITE_SUPABASE_URL` | `https://<project-ref>.supabase.co` |
   | `VITE_SUPABASE_ANON_KEY` | the **anon / publishable** key (Supabase → Project Settings → API Keys). Never the `service_role` or secret key. |

6. **Save and deploy**. The first build takes 3–5 minutes. If it stops at "Set VITE_SUPABASE_URL…", the variables are missing.

## 3. Make page links work (single-page app rule)

Amplify → your app → **Hosting → Rewrites and redirects → Manage redirects → Open text editor**, paste and **Save**:

```json
[
  {
    "source": "</^[^.]+$|\\.(?!(css|gif|ico|jpg|js|png|txt|svg|woff|woff2|ttf|map|json|webmanifest)$)([^.]+$)/>",
    "status": "200",
    "target": "/index.html"
  }
]
```

Without this, opening a link such as `/leads` directly shows "Access Denied".

## 4. Allow the new address in Supabase

Amplify shows the address, for example `https://main.d1abc2def3.amplifyapp.com`. In the `backend` folder:

```bash
npx supabase secrets set ALLOWED_ORIGINS=https://main.d1abc2def3.amplifyapp.com
```

If you keep the Vercel site too, list both, separated by a comma, no spaces, no trailing slash. Then set `site_url` in `backend/supabase/config.toml` to the same address and run (still in `backend`):

```bash
npx supabase config push
```

Until this step, sign-in on the AWS address shows "Cannot reach the server" because the functions refuse unknown websites.

## 5. Your own domain (optional)

Amplify → **Hosting → Custom domains → Add domain**, e.g. `crm.saispacerealty.com`.

- Domain on Route 53: Amplify sets up DNS and the HTTPS certificate itself.
- Domain elsewhere (GoDaddy, Hostinger…): add the CNAME records Amplify shows at your domain provider, then wait for "Available".

Then repeat step 4 with the custom address in `ALLOWED_ORIGINS`.

## 6. Checks after the first deploy

| Check | How | Expected |
|---|---|---|
| Site loads | Open the Amplify address | Sign-in page |
| Deep link | Open `<address>/leads` directly | Sign-in page, not "Access Denied" |
| Security headers | securityheaders.com → your address | Grade A, CSP report-only |
| Server only answers your site | `curl -i -X POST https://<project-ref>.supabase.co/functions/v1/login -H "Origin: https://evil.example" -H "Content-Type: application/json" -d "{}"` | 403 |
| Phone app | Android Chrome → menu → Add to Home screen | Opens full-screen |

After 3–5 days without CSP warnings in normal use, enforce the policy:

```bash
node frontend/scripts/set-csp.mjs <project-ref> --enforce
```
```bash
git add customHttp.yml frontend/vercel.json
```
```bash
git commit -m "Enforce CSP"
```
```bash
git push
```

## 7. Updating the CRM

Every `git push` to `main` rebuilds and publishes the website (`frontend/`) on Amplify automatically (about 3 minutes). Server changes (`backend/`) go to Supabase separately, from the `backend` folder: `npx supabase db push` for the database and `npx supabase functions deploy` for the functions.

## 8. Cost (check current AWS pricing)

Amplify Hosting is pay-as-you-go: build minutes, data served and storage. A CRM used by a small team typically stays within the free tier in the first year and costs a few dollars a month afterwards. Set a billing alert: AWS Console → Billing → Budgets → Create budget → monthly cost, e.g. $10.

## 9. Leaving Vercel (optional)

Once the AWS site works and staff use the new address: remove the Vercel address from `ALLOWED_ORIGINS` (step 4), then in Vercel → Project → Settings → **Delete project**.
